# EXPERIENCE — the agent's accumulated experience

> The agent's growing log of lessons. **Externalized memory of *what works and what doesn't*** — so a
> fresh, context-less session (or an autonomous loop) never repeats a dead end. Consult it BEFORE a task;
> append to it AFTER a meaningful attempt (success **or** failure). Grep, don't scroll.
>
> **Tags live inline on every entry** (not in a central list) — so one grep finds the experiences directly:
> `grep '#loop' EXPERIENCE.md` · `grep -i '#context\|#build' EXPERIENCE.md` · `grep '❌' -A4 EXPERIENCE.md`
> · `grep 'EXP-0007' EXPERIENCE.md`. Reuse an existing tag where one fits (grep to see what's in use).
>
> **Entry format (keep it short and grep-friendly).** Newest on top. Every entry starts with a stable id,
> an ISO date, an outcome marker (`✅` / `❌` / `❌→✅`), and inline `#tags`:
>
> ```
> ### EXP-0001 · 2026-01-01 · ✅ · #tag #area
> **Context:** one line — what was being done.
> **Tried / did:** the approach, briefly.
> **Result:** ✅/❌ — what happened.
> **Lesson:** the reusable takeaway (the reason this entry exists).   → link: bugs/NN · ideas/NN · plans/NN
> **Repro:** the ready-to-run command/check that verifies or applies the lesson — a weak session
>   executes a pasted command reliably, an essay it won't act on. (omit only if truly none exists)
> **Not for:** the lesson's validity range — where it does NOT apply. A documented lesson is still a
>   hypothesis; applied outside its range it kills good ideas.
> ```
>
> The `#tags` are **trigger-tags**: before a task, grep by the task's tags and QUOTE the relevant
> lessons in your report (id + one line) — or state "no relevant lessons". An unquoted recall is
> unverifiable; `/fable-judge` checks for this line.
>
> **Entries EXP-0001…EXP-0005 predate the `Repro`/`Not for` fields (added with KAIF 1.6, 2026-07-26)** —
> they were left as written rather than back-filled, because inventing a validity range after the fact
> is exactly the kind of plausible-but-sourceless text 1.6 hunts. New entries carry both fields.
>
> Skill: `/experience` (capture a lesson · recall relevant lessons).

### EXP-0026 · 2026-07-29 · ❌→✅ · #owner #brand #authorisation #release #gates #docs-scope

**Result:** ❌ **two defects, both caught by the owner within minutes, neither visible to any check I own.** (1) «кто давал это название?» → «Было принято бренд решение без владельца» — and the damning part is that the rule existed, was read in-session (canon: brand decisions need confirmation; `/release` Step 0: «ask the human for it»), and I stated it correctly MYSELF one message later. **Repro:** before publishing anything outward-facing, list its fields and ask of each: *who decided this, and is it written down?* Any field naming or presenting the product and answering "the agent" is a stop. For docs scope: **if a paragraph could be pasted into the README unchanged, it belongs in the README, not in the release notes.**
**Not for:** decisions that are cheap to reverse and invisible outside the repo — internal identifiers, file names, commit wording. ### EXP-0023 · 2026-07-29 · ❌→✅ · #philosophy #stop-rule #formats #assets #scope
**Context:** the packaged product wanted a desktop shortcut, and a shortcut wants an icon. The project has a logo PNG but no `.ico`.
**Tried / did:** wrote an ICO encoder. **(1)** PNG-compressed entries at every size — the documented modern format. **(2)** After .NET rendered that as pure noise: hand-written DIB entries for the small sizes, PNG for 256. **(3)** After .NET refused to load THAT at all: the platform's own `Bitmap.GetHicon()` + `Icon.Save`, one line, cannot produce a malformed file.
**Result:** ❌❌❌ attempt 3 produced a valid file whose structure said `biBitCount=4` — a 16-colour icon of a photographic logo. ✅ **stopped, and shipped no icon.** The stop was overdue by one attempt: `PHILOSOPHY.md` says three failed attempts mean the task was misunderstood, and it had been — I was hand-rolling a format encoder, the exact "reinventing the rocket" the document names. And underneath the technical failure sat a decision that was never mine: the logo is a 1734×907 banner, and turning a banner into a square app mark is a **brand** choice, which the canon reserves for the owner. The right deliverable was the shortcut without a custom icon, plus one sentence to him.
**Lesson:** two failure modes compounded, and they are worth separating. **(a)** The three-attempt rule is not about the attempts, it is about the *escalation*: each version here was more complicated than the last, which is the signal itself. **(b)** Before the third attempt at any *asset*, ask whether the thing being produced is a technical artifact or a **decision belonging to someone else** — a squashed logo, an invented crop, a chosen colour are all brand decisions wearing a technical costume, and no amount of encoder debugging turns them into engineering. **Not for:** assets with an objectively correct answer and a supported toolchain (resizing a square PNG, generating a favicon from an existing square mark) — there the work is mechanical and the stop rule would cost you a real deliverable.

### EXP-0017 · 2026-07-29 · ❌→✅ · #guards #regex #cyrillic #i18n #verification
**Context:** the web interface (phase 6.2) must contain no jargon — the owner's requirement in capitals, «БЕЗ ЖАРГОНИЗМОВ И СЛЕНГА». I wrote a spec that scans every dictionary string against a list of banned terms: `/\bсканир/i`, `/\bхеш/i`, `/\bSHA/i`, `/\bEXIF\b/i` and so on. It went green immediately.
**Tried / did:** ran the mandatory break-the-code pass anyway — planted «Сканирование папки, вычисляю хеши» into a real Russian string and expected the guard to go red.
**Result:** ❌ it stayed GREEN. Cause: **JavaScript's `\b` is defined over `[A-Za-z0-9_]` only**, so a Cyrillic letter is not a word character, there is no boundary transition before «С», and `/\bсканир/` can never match anything. Every Russian pattern in the guard was decoration. The same line held the opposite defect on the English side: `/\bSHA/` matched «**sha**ll» in an ordinary sentence, convicting an innocent string. ✅ Russian stems became plain substrings, English ones were narrowed (`/\bSHA-?\d/`), and the guard was re-verified red with the planted jargon before being trusted.
**Lesson:** `\b` is ASCII-only in JavaScript regexes — in any non-Latin script it silently matches nothing, which turns a guard into a comment that reports success. This bites hardest exactly where it is least visible: a *negative* assertion ("this text must NOT contain X") passes when the pattern is broken, so the bug and the desired outcome look identical. Two rules follow. **A negative guard must be verified by planting the very thing it forbids** — a positive guard fails loudly when its pattern is wrong, a negative one never does. And when a pattern list mixes scripts, expect BOTH failure modes in the same line: too narrow to ever fire (non-Latin + `\b`), and too broad to be right (a short Latin stem inside common words).
**Repro:** `node -e "console.log(/\bсканир/i.test('Сканирование'))"` → `false`; `node -e "console.log(/\bSHA/i.test('shall we'))"` → `true`. For any banned-words guard: plant a forbidden term in real content, run, expect red, restore. Guard: `tests/ui_page.test.mjs` "no jargon reaches the person".   → link: src/ui/i18n.mjs · plans/06_phase_6_2_wizard.md §7
**Not for:** patterns that are genuinely ASCII-only by nature (identifiers, HTTP headers, file extensions) — there `\b` behaves exactly as intended and removing it would loosen the check.
