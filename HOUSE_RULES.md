## 1. Постоянные правила владельца

Каждое правило — строгое, в словах агента, с одной строкой происхождения. Дословные слова владельца
живут в источнике, на который указывает строка.

### R1. Не двигать ни одного файла пользователя, пока не существуют все четыре артефакта безопасности

1. Подробная карта с пояснениями, что куда переедет (пред-сортировочный мастер-план).
2. Бэкап-коммит, к которому можно откатить исходную папку (манифест + снимок жёсткими ссылками).
3. Сухой прогон, отчёт которого почти 1 в 1 равен реальному прогону.
4. Пост-сортировочный отчёт с путём отката.
- **Исключение:** нет. Это ядро продукта, а не функция.

[OWNER] 2026-07-24 · `GOAL.md`, абзац «Перед тем как инструмент выполнит реальную сортировку…»

### R2. Документировать каждый спорный случай

1. Где дата или место назначения неоднозначны — записать конфликт и показать его в мастер-плане.
2. Никогда не выбирать победителя молча.
- **Исключение:** нет.

[OWNER] 2026-07-24 · `GOAL.md`, строка «Спортые моменты нужно документировать…»

### R3. Сохранять то, что назвал пользователь

1. Собственные имена файлов сохраняются; переименование — только при коллизии, и оно записывается.
2. Осмысленные имена папок сохраняются как вложенность внутри сезона.
- **Исключение:** технические папки (дампы устройств, `DCIM`, мессенджеры) — список в `MASTER_PLAN.md`,
  решение 2026-07-26.

[OWNER] 2026-07-24 · `GOAL.md`, строка «Если пользовательсике файлы имеют кастомные названия…»

### R4. Переиспользовать готовое, прежде чем писать своё

1. Если проект на GitHub уже хорошо решает часть задачи — взять его для этой части.
2. Своё `.mjs` писать только там, где подходящего нет; сравнение записать в `researches/`.
- **Исключение:** нет.

[OWNER] 2026-07-24 · `GOAL.md`, «Примечание об сторонних инструментах»

### R5. Перемещать файлы переименованием пути, а не копированием с удалением

1. На одном томе — `fs.rename`.
2. Между томами — явный путь «копия → сверка хеша → удаление», показанный в плане и отчёте, никогда молча.
- **Исключение:** нет.

[OWNER] 2026-07-24 · `GOAL.md`, «Дополнение владельца (2026-07-24, зафиксировано из чата)»

### R6. Настоящий архив владельца — только чтение

1. Тесты гоняются только на синтетических фикстурах (`tests/fixtures/make.mjs`), никогда на архиве.
2. Любая запись в настоящий архив требует свежего `AUTH:` — постоянное разрешение только на чтение.
3. Копировать фотографии владельца (как `KPOT_SANDBOX`) — только по его свежему слову.
4. В публичный репозиторий не попадают ни медиа, ни реальные пути, ни журналы реальных прогонов.
- **Исключение:** нет.

[OWNER] 2026-07-24 · разрешение на чтение архива — `researches/02_real_archive_survey.md`; копия песочницы —
`MASTER_PLAN.md`, фаза 5 (2026-07-28, «the owner authorised the copy»)

## 3. Стенды, окружения и устройства

KPOT — CLI и локальный веб-интерфейс над файловой системой. Проверка: сгенерировать синтетическое дерево,
прогнать инструмент, сравнить с эталоном (`AGENT_GUIDE.md` → «Test harness»).

| Стенд / команда | Для чего | Как агент до него добирается | Известные ловушки |
|---|---|---|---|
| Набор тестов | ворота перед каждым коммитом | `npm test` (`node --test` по всем `*.test.mjs`) | один файл спеков — не «прогон тестов» (EXP-0018) |
| Генератор фикстур | детерминированное грязное дерево + `expected.json` | `node tests/fixtures/make.mjs <временная папка>` — никогда не в репозитории | `expected.json` когда-то нёс mtime стенных часов (EXP-0016) |
| Один спек | итерации над одним модулем | `node --test --test-name-pattern "<re>"` | — |
| Покрытие | непокрытые ветви разрешения дат | `node --test --experimental-test-coverage` | — |
| Скан | карта: ассеты + улики + вердикты, JSON в stdout | `node bin/kpot.mjs scan <папка>` | только чтение |
| План | мастер-план по-русски; `--json` — артефакт SortPlan | `node bin/kpot.mjs plan <папка> [--json]` | пишет только в `<папка>/.kpot-runs/` (кэш + файл решений) — на архиве это нарушение R6 (EXP-0011) |
| Файл решений по папкам | «сортировать» / «как есть» для папок с неясным именем | `<папка>/.kpot-runs/папки-на-согласование.txt` | ключи — ИСХОДНЫЕ пути, ответы переживают перенос в `НА_РАЗБОР/` |
| Сухой прогон | полная симуляция тем же путём кода | `node bin/kpot.mjs apply --dry-run <папка>` | журнал отличается от боевого ровно одним флагом |
| Сортировка | единственная пишущая команда: бэкап → журнал → переименования | `node bin/kpot.mjs apply <папка>` | `--allow-no-snapshot` — явный обход для exFAT/FAT32 |
| Откат | журнал назад, файлы на место | `node bin/kpot.mjs rollback <run-id> [папка]` | идемпотентен; сухой прогон не откатывает |
| Веб-интерфейс | мастер + пульт управления | `node bin/kpot.mjs ui` | закрытие окна не останавливает сервер — есть «Завершить работу» |
| Свой безголовый браузер | увидеть и прокликать страницу | `msedge --headless=new --remote-debugging-port=N --user-data-dir=<temp>` + CDP через WebSocket | спек сервера не видит экран (EXP-0019, EXP-0024) |
| Песочница `KPOT_SANDBOX` | настоящие данные под присмотром | см. §2 | не удалять и не копировать больше фотографий без слова владельца |

## 6. Инструменты проекта

| Команда | Что делает | Что охраняет |

| `npm run package` | собирает портативный ZIP для Windows: сверяет SHA-256 вендоренного архива Node с опубликованным nodejs.org, читает подпись Authenticode на реально отгружаемом файле, собирает дерево по белому списку, пакует.
