## 1. Задача в одном предложении

Провести человека, у которого библиотеки ещё нет, по четырём шагам — папка → изучаю → план →
готово, — показывая на каждом четыре гарантии из `GOAL.md` и спросив ровно одно осознанное
подтверждение перед тем, как что-то сдвинется.

## 2. Порядок работ внутри фазы

Фаза делится надвое, и первая половина — та, где есть настоящий риск.

**6.2a — как сервер запускает прогоны (несущая часть).** Ровно один прогон одновременно; состояние
видно; ход работы идёт в браузер тем же SSE, что уже есть; ошибка прогона не роняет сервер;
подтверждение обязательно именно для сортировки.
**6.2b — лицо.** Четыре шага, словарь строк RU/EN с первой надписи, четыре гарантии внизу.

## 3. Правила, которые 6.2a обязана удержать

| Правило | Почему |
|---|---|
| **Один прогон за раз** | два `apply` над одним деревом одновременно — это гонка за файлы владельца. Второй запрос получает отказ с объяснением, а не встаёт в очередь |
| **Сортировка требует подтверждения** | владелец выбрал одно осознанное подтверждение с числами (Q4 = А). Сервер не полагается на то, что кнопку нарисовали правильно: без явного признака запрос отклоняется |
| **Прогон переживает закрытие вкладки** | решение владельца; уже проверено на уровне SSE в 6.1, теперь должно держаться и для настоящей работы |
| **Пишет по-прежнему только `src/apply/`** | сервер зовёт `src/app/phases.mjs` и ничего не делает с файлами сам |
| **Ошибка — это результат, а не падение** | упавший прогон становится состоянием `failed` с человеческим текстом; сервер продолжает работать |

## 4. Критерий приёмки 6.2a

Каждая проверка сначала ломается.

1. пока прогон идёт, второй запрос на прогон отклонён;
2. `apply` без явного подтверждения отклонён и **ничего не тронул**;
3. состояние прогона видно и доходит до браузера событиями;
4. упавший прогон оставляет сервер живым и сообщает причину по-человечески;
5. закрытие подписки не отменяет работу.
