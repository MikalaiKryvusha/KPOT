## 1. Что это за эпик, в одном абзаце

Сегодня KPOT — правильный продукт с неправильным входом: он сделан для человека с хаотичным
семейным архивом, а воспользоваться им можно только набрав `node bin/kpot.mjs plan <папка>` в
терминале. Эпик закрывает это противоречие: у продукта появляется **локальный веб-интерфейс**
(сервер на этом же компьютере плюс страница в браузере), **портативный пакет**, который достаточно
скачать и распаковать, и **человеческий язык** во всём, что программа говорит. Ядро при этом не
переписывается: интерфейс становится вторым рендерером того же самого плана сортировки, который
ядро уже умеет отдавать машиночитаемо.

## 2. Что считается сделанным (определение готовности всего эпика)

Эпик закрыт, когда **человек, который никогда не открывал терминал, скачивает архив, распаковывает
его, запускает ярлык и получает разобранную библиотеку — ни разу не увидев командной строки и ни
разу не встретив слова, которого он не понимает.** Разложенное по проверяемым признакам:

1. Скачал ZIP → распаковал → двойной клик → браузер открылся на работающей программе.
   Ни установки, ни прав администратора, ни установки Node.
2. Мастер провёл через первый полёт: папка → изучение → план → сортировка. Четыре гарантии из
   `GOAL.md` (карта · бэкап · сухой прогон · откат) видны на экране, а не спрятаны во флагах.
3. Одно осознанное подтверждение с числами перед сортировкой — и после неё кнопка отката на виду.
4. Дальше открывается пульт: три прогона можно перезапустить, папки на согласование решаются
   кнопками, новые файлы доливаются из `НОВОЕ`, каждый прошлый прогон можно откатить.
5. Закрытие вкладки браузера **не** останавливает сортировку; выключается программа явной кнопкой.
6. Ни одной строки жаргона на всей поверхности — ни в интерфейсе, ни в отчётах, ни в README для
   пользователя. Проверяется чтением вслух, а не грепом.
7. `npm test` зелёный, RULE 1 не нарушен: единственный писатель по-прежнему `src/apply/`.

## 4. Что мы сознательно НЕ делаем

Названо явно, чтобы не расползлось по ходу работы:

- **никаких миниатюр** — ваше решение, и оно снимает самую дорогую и самую тормозящую подсистему;
- **никакого доступа с других устройств**, никаких паролей и учётных записей;
- **никакого установщика**, никакой подписи кода, никакого автообновления, никакой телеметрии;
- **никаких новых тяжёлых зависимостей**: сервер на `node:http`, страница — статика; прогресс
  через `text/event-stream` (одна строка на Node), а не через WebSocket-библиотеку;
- **никакого второго исполнителя**: интерфейс ничего не сортирует сам, он зовёт то же ядро.

## 5. Архитектура на одну страницу

```
        ┌─ bin/kpot.mjs        → терминал, текстовые отчёты   (есть сегодня)
src/app/│  (композиция фаз: разведка → план → сортировка → откат)
        └─ src/ui/server.mjs   → HTTP + SSE  →  браузер «морда»   (новое)
                                     │
                                     ▼
                    src/plan/ · src/apply/  ← RULE 1: пишет только apply
```

**Находка, которая определяет первую фазу.** Композиция фаз сейчас живёт **приватными функциями
внутри `bin/kpot.mjs`** (`scanAndAnnotate` — строка 251, `planWithDecisions` — строка 267), и они
переплетены с печатью в консоль и кодами возврата. Сервер вызвать их не может. Если оставить как
есть, у интерфейса будет **своя копия** конвейера — а это ровно тот сценарий, при котором сухой
прогон и настоящий начинают расходиться, потому что у них два кода. Поэтому эпик начинается не с
красивого экрана, а со скучного выноса композиции в общий слой с двумя вызывающими.

**Три обязательства, которые создаёт ваше разделение «сервер + морда»** (перенесены сюда из
интервью, чтобы не потерялись):

1. **Явная кнопка «Завершить работу»** — раз окно больше не выключает программу, выключатель должен
   быть виден и назван человеческими словами.
2. **Повторный запуск ярлыка не поднимает второй сервер**, а находит работающий и открывает морду
   на нём. Иначе первое же двойное нажатие даст конфликт порта.
3. **Сервер — единственный писатель.** Морда не пишет ничего; RULE 1 внутренней карты остаётся в
   силе, интерфейс становится ещё одним вызывающим над `src/apply/`.

## 6. Разрез на фазы

### Фаза 6.0 — Общий слой: у продукта один исполнитель и два вызывающих

**Зачем:** без этого интерфейс станет второй реализацией продукта (см. §5).
**Что делаем:** выносим композицию фаз из `bin/kpot.mjs` в `src/app/` — функции, которые принимают
папку и настройки, а возвращают артефакты (карту разведки, SortPlan, результат сортировки, результат
отката) и **не печатают ничего**. `bin/kpot.mjs` становится тонким: разбор аргументов, вызов, печать.
**Критерий приёмки:** ни одна из существующих 192 проверок не изменила смысл; отчёты CLI побайтово
те же (сверяются золотые снимки до и после); в `bin/kpot.mjs` не осталось логики фаз.
**Риск:** это рефакторинг работающего ядра. Защита — золотые снимки вывода снимаются ДО изменения.

### Фаза 6.1 — Сервер: безопасный, одноэкземплярный, с живым прогрессом

**Зачем:** это фундамент, и именно здесь лежат все документированные способы сделать плохо.
**Что делаем:** `src/ui/server.mjs` на `node:http`. Слушает `127.0.0.1`; порт по умолчанию с
откатом на случайный свободный (как это делает Syncthing); **токен**, выданный при старте и
вшитый в открываемую ссылку (модель Jupyter); **проверка заголовка `Host`** по белому списку;
браузер открывается только после события `listening`; **одноэкземплярность** — второй запуск
находит работающий сервер и открывает морду на нём; **«Завершить работу»**; прогресс наружу
через `text/event-stream` из того же `src/core/progress.mjs`, который сегодня пишет в stderr.
**Критерий приёмки:** проверки, каждая из которых сначала проверена на сломанном коде —
запрос без токена отклонён · запрос с чужим `Host` отклонён · занятый порт приводит к запуску на
другом, и человеку показан настоящий адрес · второй запуск не поднимает второй сервер ·
долгий прогон переживает закрытие вкладки и продолжается.
**Это фаза, где безопасность не опциональна:** у программы одна опасная кнопка, и она двигает
71 606 ваших фотографий.

### Фаза 6.2 — Мастер первого полёта

**Зачем:** ваш выбор дизайна для человека, у которого библиотеки ещё нет.
**Что делаем:** четыре шага, по одной вещи на экране (папка → изучаю → план → готово), внизу
каждого — четыре галочки-гарантии из `GOAL.md`. На третьем шаге план в виде «было → станет» с
числами. Перед сортировкой одно подтверждение с числами; после — кнопка отката на виду.
**Словарь строк RU/EN заводится здесь, с первой же надписи** — переключатель языка есть с самого
начала, русский по умолчанию.
**Критерий приёмки:** первый полёт на свежем дереве-фикстуре проходится целиком в браузере, без
единой команды; сортировка запускается только после подтверждения; откат виден и работает.

### Фаза 6.3 — Пульт управления

**Зачем:** мастер прав ровно один раз; дальше он превращается в допрос.
**Что делаем:** переход на пульт, как только библиотека собрана. Наверху три карточки прогонов
(разведка · план · сортировка), у каждой состояние и своя кнопка. Дальше — то, что требует
внимания: **папки на согласование решаются кнопками «Разобрать» / «Оставить как есть»** (тонкий
слой над уже существующим `src/core/decisions.mjs`, текстовый файл остаётся запасным путём), и
спорные даты. Дальше — библиотека по годам со **ссылками «Открыть»**, которые показывают папку в
проводнике Windows. Внизу — история прогонов с откатом в каждой строке.
**Критерий приёмки:** любой из трёх прогонов запускается с пульта; ответ на папку, данный в
интерфейсе, виден в текстовом файле и наоборот; ссылка открывает именно ту папку; откат из истории
возвращает дерево побайтово.

### Фаза 6.4 — Доливка из `НОВОЕ` (идея 01)

**Зачем:** без доливки уборка деградирует — через год снова нужен большой разбор.
**Что делаем:** папка `НОВОЕ` внутри корня библиотеки, исключённая из сканов, как уже исключён
`.kpot-runs/`. На пульте блок «Новые файлы»: сколько лежит и кнопка «Разложить их». Дедуп сравнивает
новое с тем, что уже в библиотеке. Опустевшие и разобранные папки инбокса удаляются — тем же
механизмом, который вы уже одобрили 2026-07-26 для опустевших папок (пути в бэкап-манифесте, откат
воссоздаёт, пустота перепроверяется в момент удаления).
**Критерий приёмки:** доливка на фикстуре добавляет новое, не трогает лежащее, отсеивает дубликаты
против библиотеки, и полный откат возвращает и библиотеку, и инбокс.

### Фаза 6.5 — Портативный пакет и ярлык

**Зачем:** для неопытного пользователя установка — это половина продукта.
**Что делаем:** ZIP с подписанным `node.exe` (замерено 2026-07-29: подпись OpenJS Foundation
действительна, 87,4 МБ → **32,7 МБ в архиве**) плюс наши `.mjs` и запускающий `.cmd`. Первый запуск
предлагает положить ярлык на рабочий стол. Мы **не вносим ни одного неподписанного исполняемого
файла**, поэтому предупреждению SmartScreen про неизвестного издателя не на чем сработать.
**Критерий приёмки:** пакет скачан по-настоящему (через браузер), распакован на чистой машине без
Node, запущен двойным кликом — программа открылась. Что именно показала Windows на `.cmd` — записано
как факт, а не как ожидание.
**⚠️ Разведка перед этой фазой обязательна** (см. §9): «метка интернета» на распакованных файлах
пока НЕ проверена на настоящей загрузке, и обещать её отсутствие нельзя.

### Фаза 6.6 — Язык продукта: закрывающий проход

**Зачем:** ваше требование про язык — это требование к продукту, а не отделка.
**Что делаем:** сплошной проход по всей поверхности — интерфейс, отчёты, README для пользователя.
Здесь же закрывается уже висящий долг: отчёт плана до сих пор печатает вам
`dated 2012-06-15 (exif-original)`. Раздел про даты по оригиналу переписан человеческим языком
2026-07-28, строки перемещений — нет.
**Критерий приёмки:** в тексте, который видит пользователь, нет слов «хеш», «EXIF», «dry-run»,
«вердикт», «когорта» — либо они объяснены на месте одной фразой. Проверка — чтением, а не грепом.
Но язык при этом требование **каждой** фазы: эта фаза ловит остатки, а не производит работу.

## 8. Долги, которые закрываются внутри эпика

- **Жаргон в отчёте плана** (строки перемещений) — фаза 6.6.
- **Прогресс наружу только в stderr и только в терминале** — `src/core/progress.mjs` инертен, если

## 9. Что НЕ проверено и должно быть проверено до обещаний

Записано честно, потому что обещать непроверенное — это то, чего этот проект не делает.

1. **«Метка интернета» (Mark-of-the-Web).** Файлы, распакованные из скачанного браузером архива,
   её наследуют, и Windows может показать своё окно предупреждения на `.cmd`. Это другой механизм,
   не SmartScreen. Проектный ответ — предложить ярлык при первом запуске (созданный на месте ярлык
   метки не имеет), но **это нужно проверить на настоящей загрузке** перед фазой 6.5.
2. **Открытие папки в проводнике из локального сервера.** Механизм простой, но это запуск внешней
   программы по запросу из браузера — путь обязан проверяться на принадлежность корню библиотеки.
